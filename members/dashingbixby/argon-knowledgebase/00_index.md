## 1. Epistemic Source Tagging Specification

Every rule, formula, threshold, count, time window, and procedure in this knowledge base carries one of four mandatory epistemic tags. Software agents parsing these files must treat these tags as confidence and override flags:

1. **`[DOCTRINE: <source name / section / date>]`**
   - **Definition:** Explicitly stated in an official Skylit source (`academy-export.json`[cite: 1], `skylit.ai/docs`, `skylit.ai/changelog`, or `skylit.ai/learn`).
   - **Agent Handling:** Treat as authoritative Skylit system logic. Where two `[DOCTRINE]` sources disagree, both are preserved side-by-side and logged in `open_questions.md`.
2. **`[GENERAL TA]`**
   - **Definition:** Standard technical analysis or market-microstructure definitions that Skylit sources assume the reader knows (for example, how to mathematically define a candle wick, a 5-bar fractal swing high, or an Opening Range) but do not explicitly define in the text.
   - **Agent Handling:** Necessary for code implementation of "Charts First" rules. Always accompanied by an explicit statement that Skylit sources leave the exact parameter undefined.
3. **`[INFERENCE]`**
   - **Definition:** Logical deduction that bridges two or more `[DOCTRINE]` statements (for example, combining the $\pm\$0.50$ SPY deflection zone with the 3:1 R:R rule to compute minimum target distance).
   - **Agent Handling:** Treat as derived logic; verify against underlying `[DOCTRINE]` inputs.
4. **`[NOT SPECIFIED]`**
   - **Definition:** A parameter, threshold, lookback window, or tie-breaker that a software programmer requires to build a deterministic detector, but on which all reachable Skylit sources are silent or vague.
   - **Agent Handling:** **Do not hardcode a guessed constant as doctrine.** Expose any `[NOT SPECIFIED]` parameter as a configurable variable in agent code and consult `open_questions.md`.

## 4. Agent Checklist (`00_index.md`)

1. **Verify Epistemic Tag Parser:** Before executing any trading rule, check its tag (`[DOCTRINE]`, `[GENERAL TA]`, `[INFERENCE]`, or `[NOT SPECIFIED]`).
2. **Expose `[NOT SPECIFIED]` Variables:** Ensure all parameters tagged `[NOT SPECIFIED]` are loaded from a configuration file (see `open_questions.md`) rather than hardcoded as immutable constants.
3. **Enforce Module Dependency Order:** Never invoke node-level detectors (`heatseeker_node_core_attributes.md`) or flow detectors (`flowseeker_options_flow.md`) before running the chart-structure state machine (`chart_structure_fundamentals.md` and `charts_first_workflow.md`).
